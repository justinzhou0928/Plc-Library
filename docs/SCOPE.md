# 库职责与 SCADA 职责边界

> 本文回答一个选型问题：`PlcLibrary` 负责什么、SCADA/网关负责什么。  
> 结论：**PlcLibrary 是 SCADA 的南向协议接入层，不是完整 SCADA 平台。**

## 一句话边界

- **PlcLibrary 负责“把设备数据可靠、可诊断地读上来/写下去”**：协议、连接、批处理、质量、时间戳、重连、采集调度、数据分发。
- **SCADA/网关负责“把数据变成业务”**：点表/资产模型、报警/事件、历史、冗余、北向接口、操作审计、安全策略与运维。

## 职责矩阵

| 能力 | PlcLibrary（南向协议库） | SCADA / 网关（上层） |
|---|---|---|
| 协议报文/会话 | ✅ 实现与维护 | ❌ |
| 地址解析、类型编解码、批量读写 | ✅ | ❌ |
| 连接池、超时、重试、熔断、重连 | ✅ | 配置策略与容量规划 |
| 每设备轮询/推送采集循环 | ✅ 基础调度 | 扫描组/优先级/全局调度策略 |
| 热更新与采集监督 | ✅ | 配置来源、审批、发布 |
| 点位质量码、源/服务器时间戳 | ✅ 产生并透传 | 映射为业务质量、报警判定 |
| 设备发现/标签浏览 | ✅ 提供协议能力接口 | 资产建模、人工确认、映射 |
| 写命令执行/回读 | ✅ 执行协议写 | 操作票、联锁、权限、审计 |
| 设备级诊断/指标/Trace | ✅ 原始指标 | 告警、看板、SLO |
| 实时值缓存/变化订阅 | ✅ 最新值缓存 | 业务缓存、规则计算 |
| 报警/事件/SOE | ❌ | ✅ |
| 历史库/时序库 | ❌ | ✅ |
| 断网缓存/断点续传 | ❌（库内只有有界队列） | ✅ |
| 双机/双网关热备、选主 | ❌ | ✅ |
| 北向协议（OPC UA Server/MQTT/Kafka/IEC 104/REST） | ❌ | ✅ |
| 点表/资产模型/工程单位/量程/死区 | ❌ | ✅ |
| 用户/角色/操作审计/联锁 | ❌ | ✅ |
| 证书/密钥/凭据管理 | 协议安全参数 | ✅ 密钥存储、轮换、网络分区 |
| 时间同步策略 | 协议对时能力 | ✅ 全站时钟策略 |
| 组态/UI/部署/升级 | ❌ | ✅ |

## 判断规则

一个需求应该放在库里，还是 SCADA 里，看三个问题：

1. **它是否与具体协议报文/连接状态强相关？** 是 → 库；否 → 上层。
2. **它是否需要跨设备、跨协议的统一业务语义？** 是 → 上层（报警、资产、历史、冗余）。
3. **它是否是“数据可靠性”的一部分？** 连接、重连、超时、质量、时间戳 → 库；断点续传、持久队列、主备 → 上层。

## 明确不放进库的

- 报警/事件/SOE 规则与确认流程
- 历史库、时序库、报表
- 双机热备、选主、跨站点冗余
- MQTT/Kafka/OPC UA Server/IEC 104 等北向协议
- 点表/资产模型/工程单位/量程/死区
- 用户权限、操作票、联锁、审计
- 持久化断点续传（库只提供有界队列与背压）

这些如果硬塞进库，会把“协议适配层”变成“半个 SCADA”，增加耦合且难以复用。正确做法是：**库保持协议与采集语义，SCADA/网关在其上组合。**
